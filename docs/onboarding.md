# Guided business interview

Conduct this interview in the project chat.
Ask at most three focused questions at once.
Treat the stages as a coverage guide, not a form the user must complete.
Save each stage before the next one.
Explain a recommendation when the user does not know the answer.

## Stage 1: Business

- What is your business called?
- What do you sell or do?
- Which website can we inspect?
- Where do you serve customers?

Offer ideas without references and work from supplied references as equal choices.
Say: "I do not have references. Give me ideas." as an explicit available answer.
Suggest preliminary content themes after these answers.
Label them as preliminary until the audience and goals are clear.

## Stage 2: Audience

- Who should the content help?
- What questions or problems do those people have?
- Which business result matters most?
- Which languages should we use?

Ask for a specific customer example if the answer is "everyone".

## Stage 3: Content

- Do you want carousels, single images, Stories, videos, or a mixture?
- How many main posts can you support each week?
- Which topics and products should lead?
- What should the reader do next?

Recommend a two-week mix with a reason for each format.
Do not promise a follower count or viral reach.

## Stage 4: Brand

- Which colors, fonts, and spacing rules are required?
- How should the brand sound?
- Which logo versions can we use?
- What must we always include or avoid?

Request the brand kit, original logo, and licensed font files.
Show actual visual directions before a full batch.
Present seven distinct previews tailored to the business, with a short explanation for each.
Ask the user to select or refine one direction.
Allow combinations and custom instructions.
Create one finished sample in the chosen direction and get approval before a full batch.
Keep the approved sample as a versioned visual reference.

## Stage 5: Media

- Should images be generated, supplied, licensed stock, or a mixture?
- Should images contain text?
- Do you want original ideas, supplied references, or both?
- Which references should guide us, if you have any?

Inspect reference media before adapting it.
Keep image-only references free of unrequested text and sales frames.
References are optional. Use the approved direction when none are supplied.
Do not ask about music during standard setup. Automatic music is not implemented.
If the user requests music, explain the manual option and preserve that requirement until they change it.

## Stage 6: Facts and rights

- Which business facts and offers are confirmed?
- Which claims or subjects must we avoid?
- Which primary sources are suitable?
- Which assets have confirmed rights?
- Where should verified sources appear in public posts?

Keep necessary limits with the advice they qualify.
Do not turn another social post into the sole factual source.

## Stage 7: Delivery

- Which platforms and exact accounts should receive the content?
- Which timezone should schedules use?
- What is the limit for paid tools and hosting?
- Should the user review each post or each batch?

Ask about ongoing permission only after a successful test.
Explain which device or service must remain online.
Save the chosen rules without activating publication by default.

## Stage 8: Creative preferences

- Which types of posts should we create?
- How many of each type should appear each week?
- What is the main call to action?
- Which custom CTA rules should we use?
- What custom prompt should guide the content?

Offer random choices for creative preferences.
Preserve exact counts such as two funny posts and two factual posts each week.
See docs/creative-controls.md for the available controls.

## Stage 9: Storage

- Should the engine also save work to Google Drive?
- Should sync run manually or after changes?
- Which private storage rules should apply?

Explain what the backup includes before connection.
Use docs/google-drive.md to configure the user's own Google application.
Never copy another project's credentials into a new installation.
